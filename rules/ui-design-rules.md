# UI and Design Rules
- Inspect existing brand, typography, spacing, colors, component library, and patterns before designing.
- Do not invent a new visual language when a design system exists.
- Establish hierarchy, readable typography, consistent spacing, and predictable interactions.
- Prefer reusable components and design tokens.
- Support mobile, tablet, and desktop breakpoints.
- Provide hover, focus, active, disabled, loading, empty, error, and success states as relevant.
- Ensure keyboard navigation, visible focus, semantic structure, sufficient contrast, and accessible names.
- Avoid decorative complexity that harms clarity or performance.
- Do not use placeholder content in a production-ready deliverable unless explicitly requested.
