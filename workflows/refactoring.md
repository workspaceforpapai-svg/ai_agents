# Refactoring Workflow
1. State the measurable reason for refactoring.
2. Map public interfaces, callers, data contracts, and tests.
3. Define behavior that must remain unchanged.
4. Add characterization/regression tests before structural changes where practical.
5. Refactor in small steps; avoid mixing feature changes.
6. Run tests after each meaningful step.
7. Compare behavior and performance where relevant.
8. Report compatibility and remaining technical debt.
